# Deploying to Render

The Render blueprint in `render.yaml` deploys the web client and API as one
service. Keeping them on one origin lets the case access cookie work without
cross-site cookie configuration.

## Before deploying

1. Create a MongoDB Atlas database and a database user with access to that
   database. Use a strong, unique password.
2. In Atlas Network Access, allow connections from Render. The free Render
   plan does not provide a fixed outbound IP, so Atlas may require `0.0.0.0/0`;
   use a dedicated database user with access limited to this app's database.
3. Make sure your latest changes are pushed to GitHub.

## Create the Render service

1. In Render, choose **New + → Blueprint** and connect the GitHub repository.
2. Render reads `render.yaml` and creates the web service. Confirm the
   `MONGODB_URI` environment variable when prompted. Use the Atlas `mongodb+srv`
   connection string, replacing its username, password, and database name.
   URL-encode special characters in the password.
3. Start the deploy. The service builds the Vite client, then starts the API.
   Its health endpoint is `/api/v1/health`.
4. Open the service's `onrender.com` URL and create a case. Both the UI and API
   are served from that URL.

`SESSION_SECRET` is generated by Render. The default generator is mock-based;
no Gemini key is needed. To enable Gemini later, set `AI_PROVIDER=gemini`,
`GEMINI_API_KEY`, and `GEMINI_MODEL` in Render's Environment settings, then
redeploy. Never commit production secrets to the repository.

The free Render web service can sleep when idle, so its first request after
inactivity may take longer. For a continuously available app, select an
always-on plan in Render.
